# 設計メモ

## 技術スタック

| 役割 | 採用 | 理由 |
| --- | --- | --- |
| ウィンドウ・入力 | winit 0.30 | 安定版。Windows ではペンが WM_POINTER 経由の `Touch` イベント（筆圧は `force`）で届く |
| GPU 表示 | wgpu 30（Windows では DX12） | キャンバスの表示・拡大縮小・将来の GPU 合成 |
| 描画処理 | 自前（pp-core） | タイル単位で CPU 処理。依存を増やさず最適化しやすくする |

## キャンバス

- ピクセルは premultiplied alpha の RGBA8。
- レイヤーは 256×256 のタイルを疎に持つ（描いた所だけメモリを使う）。
- ブラシはストロークを一定間隔のダブに分割して src-over で描く。
- 描いた範囲（dirty rect）を貯めておき、フレームごとに 1 回だけ合成して GPU テクスチャへ転送する。
  範囲はダブの外接矩形ではなく、実際に書き換えた画素を囲む矩形にする（太い筆で前のダブと重なる所を送り直さない）。
- `StrokeBuffer` を使う筆（鉛筆・油彩・水彩・練り消し）は、ダブをタイルごとに描き、太いダブ（128×128 より大きい）は
  タイルを複数のスレッドで手分けする。すでに最大まで覆った画素と、各行で跡のかからない所は計算しない。
- UI の描き直し範囲（`DirtyRegion`）は矩形をいくつか持てる。斜めの長い直線の下書きでも、線の周りだけを描き直して送る。
- 表示は GPU が担当し、拡大縮小・移動では再合成しない。

## ペンタブレット入力

- Windows Ink（WM_POINTER）経由で、Wacom・XP-Pen・Huion などの板タブ・液タブが使える。
  winit がペンの筆圧（0〜1024）とサブピクセル座標を `Touch` イベントとして渡す。
- winit は筆圧 0 を「筆圧なし」と同じ `None` で渡すため、筆圧を一度でも受け取ったデバイスでは `None` を 0 として扱う。
- Windows Ink を切っている環境（WinTab のみ）では筆圧が取れずマウス扱いになる。必要になったら WinTab 対応を追加する。
- 筆圧カーブは CLIP STUDIO と同じく制御点を結んだ折れ線（`PressureCurve`）。いまはプリセット 3 種を `K` で切り替え、UI で編集できるようにする予定。
- 未対応：消しゴム側（ペンのお尻）、サイドボタン、傾き。winit 0.30 が渡さないので、必要なら WM_POINTER を自前で読む。

## 機能の範囲

アナログ画材と同じ程度に絞る。「アナログでも同じことができるか」を追加の基準にし、実用に欠かせないものだけ例外として入れる。

| 入れる | アナログでの対応 |
| --- | --- |
| ペン（筆圧でサイズ・濃さ）と筆圧カーブ。種類は今後増やす | ペン・鉛筆・筆 |
| 消しゴム・練り消し | 消しゴム・練り消し |
| パレット上での混色 | パレットで絵の具を混ぜる |
| レイヤー（紙モードのみ。重ねた紙として扱う） | トレーシングペーパー・セル |
| 拡大縮小・移動、キャンバスモードに応じた回転 | 紙やキャンバスを持ち替える |
| 保存 | 実用上の例外 |
| `.clip` の読み込み・書き出し | プロジェクトの目標 |

入れないもの（当面）：アンドゥ／リドゥ（どのペンも取り消せない）、キャンバス上のスポイト、カラーピッカー（数値での色指定）、フィルタ、選択範囲と変形、ブラシの大量プリセット、ベクターレイヤー、3D、アニメーション。

### パレットと混色

- 色はカラーピッカーで作らず、パレット上で絵の具を置いて混ぜて作る。
- パレットの上にもキャンバスと同じようにペンで描ける。パレットの上はいつも混色で、通った所の絵の具と混ざる（`PaletteBrush`）。
  描いてもペンの色は変わらない。消しゴムは絵の具を拭き取る。鉛筆のように絵の具を使わないペンは何もしない。
- スポイトは右クリック（または Alt + 押す）で、パレットの上でだけ使える。なぞったときは通った絵の具の色が付き、
  絵の具のない所を通っても色は消えない（離したときに最後に触れた色が残る）。
- ペン先の色を変える手段は 2 つだけにする。色見本（RGB 表）のマスに触れるか、パレット上のスポイトで取るか。
- 混色パネルは上に色見本、下にパレットを置く。絵の具のチューブは置かない。
- 色見本（`ColorChart`。24 色相 × 明るさ 9 段と無彩色 1 列）は、触れたマスの色がそのままペン先に付く。パレットへはその色のペンで描いて置く。
- 混ぜ方は光の RGB 平均ではなく、絵の具らしい減法混色（青 + 黄 = 緑）にする。Kubelka-Munk 理論の近似を自前で実装する
  （既存ライブラリの Mixbox は非商用ライセンスのため使わない）。
- キャンバス上にはスポイトを置かない。キャンバス上の色を拾う手段はない。
- 実装：`Pigment`（K/S による混色）、`Palette`（マスごとに絵の具の色と量を持つ板）、`PaletteKnife`（なぞって混ぜる）、`PaletteBrush`（ペンで描く・拭き取る）。

### 油彩の描き味

- 油彩ペンは、キャンバス上での描き方を「混色」と「上書き」から選べる（`PaintMode`、ツールプロパティで切り替え）。
- 混色では、ダブごとに下にある乾いていない絵の具を拾ってペン先の絵の具と混ぜる（`OIL_PICKUP`）。上に重ねると下の色と混ざる。
  上書きでは下の絵の具を拾わず、ペン先の色で覆う。
- 拾った色は描くうちにパレットで付けた色へ戻っていく（`OIL_REFILL`）。
- ツールプロパティで「絵の具の量」と「不透明度」を変えられる。量が少ないと、1 ストロークの中で進んだ距離に応じて
  絵の具が減り、線の終わりがかすれる（`PaintSupply`。量が最大なら減らない）。次のストロークでまた含ませ直す。水彩筆も同じ部品を持つ。
- 1 ストロークの中ではダブが重なっても濃くならない（鉛筆・水彩と同じ `StrokeBuffer`）。不透明度を下げると、線全体が同じだけ透ける。
- 混色はパレットと同じ Kubelka-Munk の計算で、ダブごとに 1 回だけ行う（画素ごとには計算しないので軽い）。

### 鉛筆と水彩筆

- 両方とも、1 ストロークの間だけ `StrokeBuffer`（描く前のレイヤーと、各画素をどれだけ覆ったか）を持つ。
  同じストロークの中ではダブが重なっても濃くならず、ストロークを重ねたときだけ濃くなる。
- 鉛筆：紙に固定した紙目の模様（`paper_grain`）の山にだけ芯が乗る。軽い筆圧ではざらつき、強く押すと埋まる。
  色は黒鉛で固定（パレットの絵の具は付かない）。
- 水彩筆：透明な絵の具として、白い紙の上で「下の見た目 × 絵の具の透過色」になるよう重ねる（黄の上に青で緑）。
  紙モードでだけ使える。油彩と同じく「絵の具の量」（`PaintSupply`）と「不透明度」（1 ストロークで付く濃さ）を変えられる。
- Gペンは後回し。

### カーソルと滑らかな回転

- キャンバスの上では OS のカーソルを隠し（`set_cursor_visible`）、UI の画像にペン先の輪郭（筆圧 1 の大きさ）と十字を描く（`BrushCursor`）。
  白の縁取りに黒い線なので、どんな色の上でも見える。パネルやメニュー・ダイアログの上では OS のカーソルに戻す。
- 「滑らかに回転」が ON の間は描かない。押した所を軸に（`PivotDrag`）、ポインタが軸のまわりを回った角度だけ表示を回す。
  軸から 12px 以内では向きが決まらないので回さない。油彩キャンバスでは使えない（90° 単位のため）。

### 筆の形と直線

- 油彩・水彩筆は筆の形（`TipShape`）を選べる：丸筆（円）、平筆（角の丸い長方形、厚み 0.3）、フィルバート（楕円、厚み 0.5）。
  傾きを読まないので、平たい筆は毛の並ぶ向きを右上がり 70°（`FLAT_TIP_ANGLE`）に固定する。横に引くと太く、その向きに沿うと細い。
  ダブの間隔は厚みを基準にする。
- ツール列の「直線」が ON のときは `StraightLine` で引く。引いている間は UI の画像に下書き（筆の幅の輪郭、`LineGuide`）だけを出し、
  離したときに 1 本のストロークとして一度だけ描く（動かすたびに描き直すと、太い筆で重くなるため）。
  筆圧は引いている間で一番強かったものを線全体に使う（ペンは押し始めと離す瞬間に筆圧が弱く、端の値では細くなるため）。

### 消しゴムと練り消し

- 消しゴム：こすったところをすっかり消す。
- 練り消し：1 ストロークごとに 4 割ほど取れる（強く押すほどよく取れる）。`StrokeBuffer` を使うので、1 ストロークの中で往復しても取れる量は同じで、
  ストロークを重ねるごとに薄くなる。下描きを薄くしたり、明るいところを抜いたりするのに使う。
- ツール列では同じ「消しゴム」の欄にまとめ、ツールプロパティで消し方を選ぶ（`TOOL_SLOTS`。欄ごとに最後に選んだものを覚える）。
- どちらも紙モードだけ。`Pen::erases` が true の道具で、ブラシサイズは描く道具とは別に共通にする（描く道具どうしも共通）。

### undo しない

- ペンは `Pen` トレイトを実装した構造体（`InkPen`、`OilPen` など）。円形のペン先 `RoundTip` は部品として各ペンが持つ。
- どのペンで描いた線も undo できない。アナログでインクや絵の具の線を消せないのと同じ扱いで、直すときは消しゴムや上塗りで直す。
  そのため履歴は持たず、取り消し・やり直しのメニュー・ボタン・ショートカットも置かない。

### レイヤー（重ねた紙）

レイヤーは「キャンバスの上に重ねた紙」として扱い、できることは紙の素材で決まる。

- 素材は 2 種類：トレーシングペーパー（下が半透明に透ける。下書き用）と透明フィルム（セル画のように完全に透明）。
- できる操作：紙を足す・外す、重ねる順番の入れ替え、紙をめくって隠す。
- 置かないもの：不透明度スライダー、合成モード（乗算など）。透け方は素材で決まる。
- 実装は `Layer` に素材（`SheetMaterial`）を持たせるだけで、描画・タイル処理は共通。
  トレーシングペーパーは合成時に、下にあるもの全体へ白いもや（約 6 割）を掛けてから自分の絵を重ねる。
- 用紙の白地は 0 番レイヤーとして持ち、利用者には見せない。用紙（1 番）は外せず、重ねた紙はそれより上に並ぶ。
- 紙を外す操作は元に戻せない（紙を捨てるのと同じ）。
- 油彩モードではレイヤーを使わない（キャンバス 1 枚に直接描く）。グレーズは透明度の高い絵の具で表現する。
- `.clip` から読み込んだレイヤーの不透明度・合成モードは保持して表示するが、アプリ上で編集できるのは素材だけにする。

### キャンバスモード

ドキュメント作成時にモードを選び、モードごとに操作の制約を変える。

| モード | 回転 | レイヤー | 想定 |
| --- | --- | --- | --- |
| 紙 | 自由回転（ボタン・キーは 15° ずつ、R+ドラッグか「滑らかに回転」で無段階） | 重ねた紙として使える | 鉛筆・ペン・水彩など |
| キャンバス（油彩） | 90 度単位のみ | なし | イーゼルに立てたキャンバス |

- 油彩キャンバスは下地（ジェッソ）を塗った 1 枚に直接描く（内部では、下地と絵の具の層を分けて持つ）。消しゴムは使えない（`Pen::usable_on` で判定）。
- いまは起動引数 `--oil` でモードを選ぶ。新規作成ダイアログができたらそこで選ぶ。

今後、モードに応じて使えるペンや紙の質感を変えることも検討する。

## 保存と書き出し

- 作品は独自形式 `.plim`（`pp-file` クレートの `plim`）で保存する。`.clip` には入らないこのアプリ独自の情報
  （キャンバスモード、紙の素材、パレットの絵の具）まで残し、開き直せば続きを描けるようにする。
- `.clip` は別に「読み込み」と「書き出し」として用意する（予定）。書き出しでは紙は普通のラスターレイヤーになり、
  トレーシングペーパーのもやは下に半透明の白いレイヤーを挟んで再現する。紙の素材・パレット・キャンバスモードは残らない。
- `.psd` / `.psb`（`pp-file` の `psd`）は「開く」から読み込める。CLIP STUDIO や Photoshop で「複製を保存」した PSD を持ち込む想定。
  読み込むと新しい作品（紙モード）になり、保存は `.plim` になる（元のファイルは上書きしない。紙に合わせて変えた情報が戻らないため）。
  - 読めるのは RGB とグレースケールの 8・16 ビット。CMYK・32 ビットなどは理由を出して断る。
  - 紙は不透明度・合成モード・マスク・フォルダを持たないので、見た目を保つように画素へ焼き込む（`pp-file` の `layered`。今後 `.clip` も同じものを使う）。
    - 不透明度とマスクは画素の濃さに掛ける。通常のレイヤーはそれぞれ 1 枚の紙にし、一番下を用紙、ほかを透明フィルムにする。
    - ほかの合成モード（乗算・スクリーンなど 26 種、式は W3C の定義）とクリッピングは、下の紙に統合する。
    - 通過のフォルダは中身を並べ、通常のフォルダは中身を 1 枚にまとめる。非表示のレイヤーは非表示の紙にする（合成モードのあるものは読まない）。
    - 色調補正・塗りつぶしのレイヤーは読まない。
  - 変えたこと・読まなかったものは、開いたときに一覧で知らせる。
  - 確認用に `cargo run --release -p pp-file --example psd_to_png -- 入力.psd 出力.png` で、読み込んだ結果を PNG にできる。
- CLIP STUDIO と同じく、ファイルメニューの「複製を保存」から `.psd` で保存できる（`pp-file` の `psd::save`）。作品の保存先や「保存済み」の状態は変えない。
  - 紙は下から順に、名前・表示・不透明度をそのままに通常のラスターレイヤーにする。めくった紙は非表示のレイヤー、用紙の白地（油彩では下地）は一番下のレイヤーになる。
  - トレーシングペーパーのもやは、その紙のすぐ下に半透明の白いレイヤー（「〜のもや」）を挟んで再現する（`.clip` の書き出しでも同じ方法にする予定）。
  - 8 ビット RGB、画素は PackBits（RLE）。作品の解像度も画像リソース（ResolutionInfo）に書く。統合した画像も入れるので、レイヤーを読まないソフトでも見た目どおりに開ける。紙の素材・パレット・キャンバスモードは残らない。
  - 形式を増やすときは `pp_file::CopyFormat` に足すと、メニューの「複製を保存」に並ぶ。
- `.plim` の中身：識別子と形式の版のあとに、チャンク（4 バイトの種類 + 8 バイトの長さ + 中身）を並べる。
  `DOC `（大きさ・モード・選んでいる紙・解像度。解像度は後から末尾に足したので、古いファイルにはなくモードの既定の値になる）、`LAYR`（レイヤー 1 枚ずつ、描いたタイルを zlib 圧縮）、`PALT`（パレット）。
  知らないチャンクは読み飛ばすので、項目を足しても古い版で開ける。読めない変更をしたときだけ版を上げる。
- 保存はいったん別名で書いてから置き換えるので、途中で失敗しても元のファイルは壊れない。
- PNG 書き出し（`pp-file` の `png`）は見た目どおりに合成した 1 枚。PNG は zlib と CRC だけなので自前で書き、依存を増やさない。
- 作品はタブで複数開ける。タブごとに絵・表示位置・保存先・パレットを持つ（`pp-app` の `Work`）。
  パレットは作品と一緒に保存するので作品ごとに持ち、表に出ている作品のものだけを混色パネルに載せる。
- JPEG 書き出し（`pp-file` の `jpeg`）も自前で書く。ベースライン、規格の標準ハフマン表、色差は間引かない（4:4:4。線画の色の縁がにじまない）。
  品質（1〜100）は libjpeg と同じ計算で量子化の表を伸び縮みさせる。透明は持てないので、透けている所は白い紙の上に置いた色にする。
- 画像の書き出し形式は `pp_file::ImageFormat` に足すと、メニューの「画像を統合して書き出し」にも並ぶ。いまは PNG と JPEG。
- 作品は解像度（`Document::dpi`）を持つ。画素の数は変えず、cm などとの換算と、書き出す画像への記録に使う。
  新規作成ではモードの既定（紙 350dpi、油彩 200dpi。よく使う大きさと同じ）、PSD から開くとファイルの解像度になる。
  PNG（pHYs）・JPEG（JFIF）・PSD には書き出す解像度を記録する。
- 書き出すときは、CLIP STUDIO の「出力サイズ」と同じく、大きさの決め方を 3 通りから選ぶダイアログを出す（一辺 20000 ピクセルまで）。
  - 拡縮率：作品に対する倍率（10〜1000%）。解像度は作品のまま。175% は 200dpi の油彩キャンバスを 350dpi にする倍率。
  - 出力サイズ：幅と高さ（px・mm・cm・in）。縦横比は作品のままで、片方を変えるともう一方も変わる。cm などは作品の解像度で画素に換算する。
  - 解像度：紙の上の大きさは作品のまま、解像度だけ変える（350dpi の作品を 600dpi にすると約 171%）。
  - 決め方を切り替えても、書き出す大きさは変わらない（新しい欄にはいまの大きさを入れる）。決め方・単位・倍率・品質は次に開いたときに引き継ぐ。
  - JPEG では品質（すぐ選べるのは 60・80・90・100、はじめは 90）も決める。
  拡大・縮小は `pp_file::OutputSize` で、縮小は面積の平均、拡大は双線形補間。出力を 256 行ずつ作るので、合成用のバッファは小さいまま。
- 「新規」のダイアログでは、キャンバスモードと用紙の大きさを決める。大きさは幅・高さを数字で入れる（16〜10000 ピクセル）か、よく使う大きさから選ぶ。
  よく使う大きさは、紙では A4・B5 など（350dpi）、油彩キャンバスでは F・P・M の号数（200dpi。油彩は描くたびに混色を計算するので、紙より粗くして軽くする）。
- 数字の欄（`NumberField`）は、マウスやShift+矢印での選択、Ctrl+A、Delete、Home/End、ホイールでの増減（10、Shift で 1、Ctrl で 100）に対応する。クリップボード（コピー・貼り付け）はまだない。
- ファイルのダイアログは Windows 標準のもの（rfd）。Windows 以外は開発中の確認用で、作業フォルダの決まった名前を使う。

## UI

ショートカットも可能な範囲で CLIP STUDIO に合わせる。

- 文字はなるべく置かず、ボタンは絵柄（`ui/icons.rs`）にする。名前や説明はポインタを載せたときに出す（`Panel::tooltip`）。
  見出しやメニュー、紙の名前など、文字でないと分からないものだけ文字にする。
- ツールプロパティには、CLIP STUDIO のブラシサイズパレットと同じく、大きさの見本（点の一覧）を置き、押すとその大きさになる。
- 実装は `pp-app/src/ui`。各パネルは `Panel` トレイトを実装した構造体で、操作の結果を `Action` として App に返す。
- パネルは CPU で画面と同じ大きさの 1 枚の画像に描き、変わったパネルの範囲だけ GPU に送る。キャンバスの区画は透明にして、
  下に描いたキャンバスを見せる。描画はキャンバスと UI の 2 枚の四角形だけ。
- 文字は OS の日本語フォント（Meiryo UI → 游ゴシック → MS ゴシック）を fontdue でラスタライズする。
- Windows の表示スケール（`scale_factor`）に合わせて、区画・文字・パレットを拡大する。

## 負荷テストで確かめること

内部処理はいずれ一般的なペイントソフトのやり方に合わせる。今は下の形のままにしておき、負荷テストのときに見直す。

- 太いダブを手分けするスレッドは、ダブ 1 つごとに立ち上げている。待ち時間は短くなる一方で、立ち上げの手間の分だけ CPU 時間の合計が増える
  （太さ 300 の線 1 本で、油彩 120→150ms、練り消し 130→180ms。水彩は無駄な計算を省いた分 270→230ms に減った）。
  描いている瞬間は複数のコアが動くので、使用率は上がる。描いていないときと、128px 以下の筆は変わらない。
  - 候補：スレッドを使い回す（スレッドプール）。描いている間だけ待機させておけば、立ち上げの手間はほぼなくなる。
- 太さ 600 ほどでは、入力 1 回で最大 10〜16ms かかる（描き始めの 1 つ目のダブが一番重い）。
  - 候補：ダブを重ねて押すのをやめ、ストロークの線からの距離で各画素を 1 回だけ計算する描き方。
- 測り方：`cargo run --release -p pp-core --example stroke_bench`（筆ごとに太い線 1 本の時間）、
  `event_bench`（油彩で、入力 1 回ごとの描画と合成の時間、最大値）。
